# NEXUS Layer 2 Relationship Graph

The Layer 2 Relationship Graph is the canonical knowledge and intelligence core of the NEXUS Memory architecture. Positioned directly on top of the append-only **Layer 0 (L0) Event Store** and **Layer 1 (L1) Materialized Views Projection Framework**, the L2 Graph Engine transforms isolated state records into an active, trace-explainable connected network of intelligence.

---

## 1. Core Architectural Guidelines

1. **Not a Visualization Layer:** The L2 Graph is the single source of truth for semantic relationships inside NEXUS. Every relationship must be deterministic and reproducible from memory.
2. **Strict Provenance Verification:** Relationships without evidence can never exist. Every GraphEdge must trace backward through:
   `GraphEdge` $\rightarrow$ `L1 Materialized View / Projection` $\rightarrow$ `L0 Event` $\rightarrow$ `L0 Causal Chain Sequence` $\rightarrow$ `Memory`.
3. **No Manually Created Links:** Relationships are strictly derived through chronological replay processing of L0 Events and L1 views.

---

## 2. Standardized Node and Relationship Types

The Graph enforces strict singular type categorization to maintain semantic structure and prevent circular/label corruption.

### 2.1 Supported Nodes (Singular Forms)
- **Coin:** Represents an asset/cryptocurrency (e.g., `"BTC"`, `"ETH"`, `"SOL"`).
- **Whale:** Tracked on-chain wallets or high-net-worth actor IDs.
- **News:** News articles, headlines, or published social intelligence units.
- **Decision:** Automated trade or calibration decisions generated by the AI Council or scoring engines.
- **Portfolio:** Managed portfolios holding trade state and margins.
- **Strategy:** Builtin or custom trading strategies (e.g., `MeanReverting`, `Breakout`).
- **Indicator:** Quantitative market indicators (e.g., `RSI`, `MACD`, `Volume`).
- **Market Regime:** Classified macroeconomic regimes (e.g., `BULL_TREND`, `HIGH_VOLATILITY`).

### 2.2 Supported Relationships
- **influenced_by:** Node is causally influenced by another (e.g., `Indicator` influenced_by `Coin`, `Market Regime` influenced_by `Coin`).
- **traded:** Transaction relationship indicating execution (e.g., `Portfolio` traded `Coin`, `Whale` traded `Coin`).
- **accumulated:** High-volume buying activity (e.g., `Whale` accumulated `Coin`).
- **distributed:** High-volume selling/distribution activity (e.g., `Whale` distributed `Coin`).
- **mentions:** Explicit reference in media or decisions (e.g., `News` mentions `Coin`, `Decision` mentions `Coin`).
- **follows:** Strategy tracking (e.g., `Strategy` follows `Indicator`).
- **confirmed_by:** Decision alignment (e.g., `Decision` confirmed_by `Indicator`).
- **contradicted_by:** Divergence in decision factors (e.g., `Decision` contradicted_by `Indicator`).
- **belongs_to:** Hierarchical ownership (e.g., `Strategy` belongs_to `Portfolio`, `Decision` belongs_to `Portfolio`).
- **generated:** Trigger actions (e.g., `Decision` generated `Strategy`).

## 3. Database Schema Specification

The L2 Graph uses persistent relational tables representing graph topology and consistency state.

### 3.1 GraphNode (`l2_graph_nodes`)
- `id` (Integer, Primary Key)
- `node_type` (String, e.g., `"Coin"`, `"Whale"`)
- `external_id` (String, unique identifier, e.g., `"BTC"`)
- `properties` (JSON, arbitrary properties)
- `created_at` / `updated_at` (DateTime with timezone)
- *Constraint:* Unique Constraint on `(node_type, external_id)`

### 3.2 GraphEdge (`l2_graph_edges`)
- `id` (Integer, Primary Key)
- `source_node_id` (Integer, ForeignKey to `l2_graph_nodes.id`)
- `target_node_id` (Integer, ForeignKey to `l2_graph_nodes.id`)
- `relationship_type` (String)
- `confidence` (Float, defaults to `1.0`)
- `provenance` (JSON tracking metadata)
- `supporting_event_ids` (JSON List of L0 UUIDs)
- `supporting_projection_ids` (JSON List of L1 View Names)
- `created_seq_id` (Integer, L0 sequence index)
- `created_at` / `updated_at` (DateTime with timezone)
- *Constraint:* Unique Constraint on `(source_node_id, target_node_id, relationship_type)`

### 3.3 GraphSnapshot (`l2_graph_snapshots`)
- `id` (Integer, Primary Key)
- `snapshot_id` (String, UUID)
- `last_sequence_number` (Integer, max sequence)
- `nodes_data` (JSON)
- `edges_data` (JSON)
- `integrity_hash` (String, SHA-256)
- `created_at` (DateTime)

## 4. Graph Replay & Verification

The L2 Graph supports deterministic sequence-ordered replays:

1. **Full Replay:** Completely wipes current nodes and edges, then streams all L0 Events chronologically from sequence 1, processing and rebuilding topology.
2. **Incremental Replay:** Queries the highest sequence number processed in the active graph (`max(created_seq_id)`) and streams only subsequent L0 events to bring the graph state up to date.
3. **Replay Verification:** Audits determinism by comparing the graph integrity SHA-256 hash before and after execution of full replays. A valid replay must generate an identical hash every single time.
4. **Replay from Snapshot:** Restores graph state from a saved `GraphSnapshot`, verifies the SHA-256 integrity hash, and then triggers an incremental replay from the snapshot's sequence point onwards.

---

## 5. Advanced Graph Query Capabilities

The engine implements advanced mathematical graph operations to support semantic intelligence discovery:

- **Neighbor Lookup:** Identifies all directed incoming and outgoing edges for any specified node ID, together with relationship types and confidence levels.
- **Shortest Path:** Implements Breath-First Search (BFS) to find the shortest directed path between any start and destination node, returning detailed path steps with relation transitions.
- **Connected Components:** Identifies weakly connected graph components, grouping connected node sets together.

## 6. Generic Graph REST API Reference

All endpoints are generic, extensible, and registered under the `/graph` prefix in FastAPI:

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| **GET** | `/graph/nodes` | Retrieves list of nodes with optional filters on `node_type` and `external_id`. |
| **GET** | `/graph/node/{id}` | Retrieves a single node's detailed attributes by database ID. |
| **GET** | `/graph/edges` | Retrieves list of relationship edges with filters. |
| **GET** | `/graph/neighbors/{id}` | Returns directed neighbors of a node. |
| **GET** | `/graph/path` | Returns shortest path between start and end node database IDs. |
| **GET** | `/graph/metrics` | High-density topology and performance metrics (counts, density, orphans, snapshots). |
| **GET** | `/graph/health` | Diagnostics regarding consistency, sequence synchronization lag, and dangling edges. |
| **POST** | `/graph/replay` | Triggers a full or incremental replay of the L0 event log. |
| **POST** | `/graph/snapshot` | Backs up the graph state into a cryptographic SHA-256 snapshot. |
| **POST** | `/graph/snapshot/restore` | Restores graph state from snapshot after validating the integrity hash. |
